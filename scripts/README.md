# Workspace tooling

Общие скрипты на TypeScript для Node, Bun и Deno. Для управления зависимостями
и упаковки по-прежнему требуется Bun; Git/npm используются соответствующими командами.

## Структура

- Корень `scripts/` — запускаемые команды; пути сохранены для package scripts.
- `lib/` — общие функции, без запуска CLI при импорте.
- `tests/` — тесты tooling на временных файлах и репозиториях.
- `tsconfig.json` — строгая проверка всех TypeScript-файлов, включая вложенные.

## Манифест исходников при dist/release

И dist, и вызывающий его release отправляют в main отдельный source release-коммит
с npm-диапазонами вместо workspace-ссылок. Например workspace:^ для types@0.5.1
становится ^0.5.1; workspace:~ — ~0.5.1; workspace:* — 0.5.1. Замена применяется
к dependencies, devDependencies, peerDependencies и optionalDependencies.
Локальный package.json сохраняет workspace-ссылки. main и тег v<версия> отправляются
атомарно из временного clone без force; __dist__ получает chore: release v<версия>.
Локальный HEAD не переключается на публикационный коммит. Поэтому origin/main
может отличаться от локальной main манифестом: не делайте слепой git pull с заменой
workspace-манифеста. Новые выпуски связывают обе линии истории merge-коммитом.
Исходники нужно коммитить заранее; допускается только незакоммиченное изменение
поля version, которое делает release. Другие изменения манифеста блокируют dist.
Существующий remote tag допускает повтор только при совпадающем дереве файлов.

## dist: исходники, тег и дистрибутив

`bun run dist <пакеты>` теперь сначала собирает пакет, затем отправляет его
исходный коммит в `origin/main` вместе с annotated-тегом `v<package.version>`
(атомарный push), после чего обновляет `origin/__dist__` с сообщением
`chore: release v<package.version>`. Повторный запуск с тем же исходным коммитом
допустим; тег на другом коммите не перезаписывается. Одинаковый dist пропускается.
Нужен собственный Git пакета, чистая ветка main и предварительный коммит изменений.
Автокоммитов исходников и force push нет. `--dry-run` не создаёт тег и не пушит.
Атомарность main+tag не распространяется на отдельную отправку __dist__;
после сбоя повторите dist с тем же коммитом и версией.

При release с повышением версии допускается незакоммиченное изменение только
поля version. Оно включается в изолированный source release-коммит, не затрагивая
локальные workspace-диапазоны.

## Команды

| Файл | Назначение |
| --- | --- |
| `workspaces.ts` | Сборка и проверки выбранных пакетов или `--all` |
| `workspace.ts` | Подключение репозиториев, scan и status |
| `build-package.ts` | Сборка одного пакета из его рабочего каталога |
| `update.ts` | Обновление зависимостей workspaces |
| `pack.ts` | Создание npm-архивов |
| `dist.ts` | Отправка дистрибутива в Git `__dist__` |
| `pub.ts` | Публикация npm, авторизация и staged recovery |
| `release-command.ts` | Планирование версий, проверки и управление выпуском |
| `tui.ts` | Интерактивное меню |
| `subtree.ts` | Legacy export; заблокирован в submodule workspace |

## Общие модули

- `lib/format.ts` — вывод CLI и запуск команд.
- `lib/release.ts` — сборка, упаковка и подготовка dist.
- `lib/release-compare.ts` — сравнение с опубликованным пакетом.
- `lib/release-version.ts` — повышение SemVer.
- `lib/npm-registry.ts` — чтение версии из npm и ожидание видимости.
- `lib/npm-stage.ts` — проверка staged-публикаций.

```sh
bun run release:test
bun run workspace:test
bun exec tsc -p scripts/tsconfig.json
```

Пути команд намеренно не перемещены: сборки пакетов ссылаются на
`../../scripts/build-package.ts`. Перемещение внутренних модулей не требует
редактировать каждый независимый репозиторий пакета.
